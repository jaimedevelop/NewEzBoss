# Finance ledger

The `/finances` page manages manually entered or imported records using the authenticated `/finance-records` API. Records belong to the authenticated account and require finances page permissions. Apply `ezboss-api/src/db/schema/077_finance_records.sql` through the existing migration process and deploy the API before using the page. This change does not run migrations or deploy services.

Imports accept Excel (`.xlsx`, `.xls`), CSV, and a JSON array of flat objects. The first nonempty spreadsheet row is the header. Choose a worksheet and match its columns, then review the first five rows before importing. English and common Spanish names match automatically; all matches are editable. Unmapped fields are blank and unused source columns are omitted. Imports append; importing the same file again intentionally creates new rows. Retrying a failed import uses the same IDs to avoid duplicate insertion after an uncertain network response.

Files are parsed in the browser. Maximum file size is 10 MB, import size is 1,000 mapped rows / 900 KB, and each cell is limited to 2,000 characters. Values remain text to retain reference numbers, source date formats, and currency formatting. There are no computed totals yet. Spreadsheet formulas import their cached displayed values; formulas are not executed or stored.

Rows can be added, edited, searched, and deleted with confirmation. Edits check the row version to prevent overwriting a concurrent edit. On a conflict, close the editor and reload before editing again. Newly issued invoices automatically create one finance row in the invoice transaction, with invoice date, estimate and invoice numbers, P.O. number, service address, customer, and issuing agent. The estimate and invoice cells link to their document pages. Document links are preserved when other cells are edited. Linked rows read approved payments directly from the document Payments tab (the source estimate ledger for linked invoices). The payment amount is red at zero, yellow for partial payment, and green when paid in full. Payment method and latest payment date are derived as well; multiple methods have a Payment Methods popup with each payment’s method, amount, and date. These three linked cells are read-only; edit payments in the document. The table refreshes payment summaries when loaded or when the window regains focus. Manual/imported rows and completion fields remain editable. Migration `096_backfill_invoice_finances.sql` adds existing invoices (including archived invoices) once, preserving existing linked rows and edits. Legacy invoices without a separate source estimate receive only an invoice link. Historical dates fall back to the document creation date when the issuance date is unknown. Manually entered/imported rows are preserved; their free-text invoice numbers are not treated as document links. Apply migration `095_finance_invoice_link.sql` and `096_backfill_invoice_finances.sql` before deploying this integration.

Import checks: from the workspace root, run `node --import ./ezboss-api/node_modules/tsx/dist/loader.mjs --test NewEzBoss/tests/financeImport.test.ts`.
